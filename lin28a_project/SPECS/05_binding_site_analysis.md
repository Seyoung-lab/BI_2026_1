# SPEC05: LIN28A binding-site count and position analysis

## Goal

Reprocess the LIN28A binding-site table from Supplementary Table S3 and integrate binding-site-level features with the candidate direct LIN28A-mediated translational repression targets identified in Spec 03 and annotated in Spec 04.

The main biological question is:

> Do LIN28A binding-site burden or binding-site position relate to the strength of translational derepression after Lin28a knockdown?

This spec adds a data-processing component beyond Table S5 by using the binding-site-level information from Table S3.

---

## Background

Spec 03 used transcript-level summary data from Table S5 to define candidate direct LIN28A-mediated translational repression targets.

Spec 04 classifies the high-confidence candidates into functional subclasses.

Spec 05 now asks whether the LIN28A binding-site architecture itself provides additional information.

Possible features include:

1. number of LIN28A binding sites per transcript,
2. strongest binding-site score per transcript,
3. average binding-site score per transcript,
4. binding-site region, such as 5′UTR, CDS, or 3′UTR, if available from Table S3,
5. whether high-confidence candidates have more binding sites than non-candidates.

### 2. Identify transcript-level key columns

From Table S3, identify columns corresponding to:

* transcript accession or RefSeq transcript ID,
* gene symbol, if available,
* binding-site coordinate or position, if available,
* binding-site score, such as CRES, entropy, FDR, alignment depth, or similar,
* binding-site region annotation, such as 5′UTR, CDS, 3′UTR, exon, intron, if available,
* sequence motif or hexamer information, if available.

Important:

* Do not assume column names.
* Print actual column names using `repr(col)` before mapping.
* If a feature is unavailable, record it as unavailable and skip that sub-analysis.
* Do not invent region annotations.

### 3. Create transcript-level binding-site features

Aggregate binding-site-level records to transcript level.

At minimum, calculate:

* `binding_site_count`
* `has_binding_site`

If score columns are available, also calculate:

* `max_binding_site_score`
* `mean_binding_site_score`

If read depth or CRES-like columns are available, also calculate:

* `max_CRES`
* `mean_CRES`
* `max_read_depth`
* `mean_read_depth`

Use only columns that actually exist in Table S3.

Save transcript-level binding-site features as:

* `lin28a_project/results/tables/05_binding_site_features_by_transcript.csv`
